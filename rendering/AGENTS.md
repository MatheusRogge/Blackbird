# rendering

wgpu 30 renderer (Vulkan backend forced). Contains the render graph, every render/compute pass, the deferred PBR + clustered lighting + CSM shadows + DDGI pipeline, the 2D sprite renderer, camera/light entities and the GPU profiler. Depends on `engine_core` and `assets` only. Re-exports `wgpu`.

## Features
- `rendering_2d` (default): the `rendering_2d` module.
- `debug`: `DebugLayer` (an egui `UiLayer`: F1 overlay with frame timing and memory tabs, `RenderDebugFlags` toggles / DDGI tuning folded below). Pulls in `egui` + `ui`.

## Render graph

### Building
A `RenderGraphBuilder::build(self, device, surface_config) -> (RenderGraph, ResourceId)` returns the graph and the **output resource id** (the surface, created with `create_external_resource()`).

The pass constructor convention is `XPass::new(&mut graph, upstream_outputs…, shader) -> (XPass, XOutputs)`. The constructor allocates its output resources with `graph.alloc_resource_id(desc)` and returns the ids in an `XOutputs` struct for downstream passes. Then `graph.add_pass(device, pass)` registers it, creates a bind group layout from `layout_entries()` if there is one, and calls `bind_node_id`.

`ResourceDescriptor` variants:
- `ScreenTexture`: sized to the surface and reallocated on resize. **Transient**: screen textures with the same format + usage whose lifetimes in the pass order don't overlap share one physical texture. Contents are undefined after the last reader in a frame, and the first writer must clear or fully overwrite it. A screen texture some pass reads before any pass writes it is never aliased.
- `Texture`: has an explicit size but is *also* resized to the surface on resize.
- `FixedTexture`, `Fixed3DTexture`: never resized.
- `UploadBuffer`: CPU-written (`queue.write_buffer`), GPU **read-only**. Packed with every other `UploadBuffer` into a few `UploadArena` pages on the first `execute` (offsets aligned to the device's uniform/storage offset alignment). The arena is then sealed: adding an `UploadBuffer` later trips a `debug_assert!`. Use this for uniforms, params, light lists, BVH data.
- `Buffer`: a dedicated buffer. Use it for anything bound as `read_write` storage (`light_grid`, `light_indices`, `ray_radiance`, `ray_direction`). wgpu tracks usage per buffer, not per range, so a GPU-written range inside a shared page would conflict with the read-only ranges bound in the same pass.
- `ExternalView`: never allocated. Use `import_texture` / `update_imported`, or it's the surface.

### Executing (`RenderGraph::execute`, every frame)
1. **Compile** (cached, redone after `add_pass` / `add_subgraph`): walk backwards from the output resource, and from every pass whose `has_side_effects()` is true, through `writes()` → `reads()` to find the needed passes, then topologically sort them (Kahn, ties broken by lowest `NodeId`). `reads()` / `writes()` must therefore be static.
2. On the first frame build the `UploadArena`. Every frame, `GeometryArena::sync` uploads new meshes and frees removed ones, and `FrameArena::begin_frame` resets the frame cursor. When a screen texture is unallocated (first frame, resize, graph change), assign and allocate all screen textures through `texture_pool::assign`. Then lazily allocate every other unallocated non-external resource.
3. Rebuild the graph-managed bind group (from `binding_resources()` + `samplers()`) for **every** pass that has one. This happens every frame.
4. For each pass in order, build a `PassContext { views, textures, buffers, bind_group, upstream, surface_size, geometry, frame }` holding only that pass's declared reads + writes. `buffers` holds `BufferRange`s: bind with `.binding()`, write with `.write(queue, ..)` / `.write_at(..)`, slice with `.slice()`. Never use `as_entire_binding()` or offset 0 on a graph buffer, because it may share a page. The output id maps to the swapchain view. Then call `pass.execute(device, queue, encoder, &ctx, world)` wrapped in CPU and GPU timing.
5. Return one `CommandBuffer` and publish `ArenaStats` in `FrameStats.memory`. `Renderer` submits the buffer, plus the overlay buffer if there is one, then calls `schedule_gpu_readback`.

**Rules that follow from this:**
- A pass is **culled** unless something on the path to the output reads a resource it writes, or it returns `has_side_effects() = true` (e.g. `prev_frame`, which only fills a texture read next frame). Every resource a pass touches must appear in `reads()` / `writes()`, or the pass is dropped, misordered, or finds the id missing from `ctx`.
- There is one writer per resource (the `writer_of` map keeps the last one). Ping-pong patterns (DDGI atlases) declare both slots and track the active one with an `Arc<AtomicUsize>`.
- The order of independent passes is deterministic (lowest `NodeId` first), but it's an implementation detail. If one pass must run before another, add a read/write dependency. Texture aliasing is computed from this order.
- A pass-owned uniform should be an `UploadBuffer` declared in the constructor and listed in that pass's own `writes()`, so it lands in `ctx.buffers`. Shadow cascade VPs share one `UploadBuffer` at a 256-byte stride with a dynamic-offset bind group.
- `queue.write_buffer` calls made during `execute` all land before the frame's command buffer runs.
- Most passes build their pipelines **lazily on first execute** and own extra wgpu objects themselves (own bind groups, material texture caches). Graph bind groups are only for the simple case. Pass-cached bind groups that reference screen textures must be dropped in `on_resize`, which is when aliasing is reassigned.

### Arenas
- `GeometryArena` (`ctx.geometry`): one vertex + one index buffer, sub-allocated with `offset-allocator`. Geometry is keyed by the addresses of a mesh's `vertices` / `indices` `Arc`s (the arena keeps a clone of both, so an address can't be reused while its entry lives) and refcounted, so meshes cloned from one `Mesh` upload once and the data is freed when the last of them goes. A mesh whose `Arc`s are replaced moves to the new data. Each mesh entity (`EntityKey`) gets its own slot in the **instance buffer** of `GpuModel { model, normal, material, base_color, emissive, transmission, attenuation }` (normal = inverse-transpose; `material` = [alpha cutoff or 0, double-sided 0/1, metallic, roughness]; `base_color` = the factor; `emissive.rgb` = emissive factor × strength; `transmission` = [factor, IOR, volume thickness (mesh-local), attenuation distance or 0 for none]; `attenuation.rgb` = volume attenuation color; `diffuse_transmission` = [color rgb, factor]), rewritten from `Mesh::transform` and factors every frame, so per-instance transforms and material edits work on shared geometry. `MeshDraw` (`ctx.geometry.get(key)`) carries the mesh's local-space `bounds` (culled with by `shadow`, `gbuffer`, `reflection_probe`, `transparent`) and a `geometry` id equal for meshes sharing data. Keep the WGSL `Model` structs in sync with `GpuModel`. When full it rebuilds bigger buffers and re-uploads every live geometry (`generation` bumps). Never hold a buffer across frames.
- **Instanced draws** (`InstanceList`, `Batch`): instance slots of meshes sharing geometry aren't contiguous, so `gbuffer`, `shadow` and `reflection_probe` each own an `InstanceList`: per frame `begin(device, max_ids)` (reserves room for every id the pass can push, replacing the buffer and bumping its `generation` if needed, so the buffer bound while encoding is the one written), `batch(Vec<(key, order, &MeshDraw)>)` per view (sorts by key then geometry; consecutive meshes with equal key and geometry become one `Batch { key, indices, base_vertex, instances, order = their smallest order }`), then `finish(queue)` uploads the ids (queue writes land before the frame's commands run, so batches are encoded before it). Draw with `draw_indexed(batch.indices, batch.base_vertex, batch.instances)`; shaders read `models[instance_ids[instance_index]]`: `gbuffer.wgsl` group 2 binding 1, `shadow.wgsl` group 1 binding 1 (vertex only; `vs_glass` passes the resolved slot to the fragment stage), `lighting.wgsl` group 0 binding 9 (`probe_instance_ids`, `vs_probe` only; `vs_probe` also passes the slot on as `instance`). Keys: gbuffer (double-sided, `MaterialKey`); shadow `()` for opaque, albedo key for masked and glass (glass tint blends commute, up to float rounding); reflection probe (masked, `MaterialKey`) with batches sorted front to back by their nearest mesh. `transparent` still draws one mesh per call (`models[instance_index]` with `draw.instances()`) since it sorts back to front. Bind groups on the ids are keyed by (geometry generation, instance list generation). `InstanceList::counts` feeds `Pass::draw_counts`, shown per pass in `FrameStats` (`PassStats::draws`: draws and meshes).
- `FrameArena` (`ctx.frame`): `alloc(device, queue, data, align) -> FrameSlice` for data that changes every frame (sprite instances). It resets each frame. On overflow that frame falls back to a one-off buffer and the arena grows at the next `begin_frame` (`generation` bumps). A bind group built on it must be rebuilt when `generation` changes.

### Writing a new pass
0. If the pass only samples screen textures and uniforms into one output, use `FullscreenPass::new(graph, name, inputs, uniforms, format, shader)` and skip to step 4 (that's how `composite` is built).
1. Create `pass/my_pass.rs` with `struct MyPass { node_id: Option<NodeId>, …ids, shader, pipeline: Option<…> }` and `MyOutputs`.
2. `impl PassDesc` (`name`, `reads`, `writes`, optionally `layout_entries` / `binding_resources` / `samplers`) and `impl Pass` (`bind_node_id`, `execute`, optionally `on_resize`).
3. Add `pub mod my_pass;` to `pass/mod.rs`, wire it in `pbr/builder.rs`, and make sure a downstream pass reads its output.
4. Add the WGSL to `sandbox/shaders/`, pass it through `RenderGraphPBRBuilder::new` (new parameter), and update `sandbox/src/main.rs`, `editor/src/main.rs` **and** `player/src/main.rs`.

## PBR pipeline (`pbr/builder.rs`)

| Pass | Kind | Reads (world / graph) | Writes |
|------|------|------------------------|--------|
| `camera` | upload | first `Camera` | camera uniform (view_proj, inv_view_proj, inv_view, depth_params = (near, far, frame index mod 1024, 0), prev_view_proj = last frame's view_proj, or this frame's on the first). Shaders may declare only a prefix of it |
| `light_upload` | upload | camera + all lights → **view space**, meshes, debug flags | point/spot/area/sky buffers, counts, `ShadowedLights` uniform. Appends one **one-sided area light per flat emissive mesh** (`light::emissive::fit`: area-weighted normal coherence ≥ 0.95, smallest edge-aligned rectangle; cached per mesh `EntityKey`), with luminance = emissive factor × strength × the emissive texture's mean, brightest first after the scene's area lights, skipping < 0.01 lm; off with the `emissive_lights` debug flag. Then scores every local light by flux / (distance to camera² + 1) and hands them to `ShadowSlots` (none with Shadows off), which shadows the top `MAX_SHADOWED_LIGHTS` (32). Spot lights with an outer angle ≤ 60° get one face (field of view = outer cone + 0.1 rad), everything else a cube of six. A light keeps its slot while it stays selected with the same shape (spot or cube), so reranking doesn't drop its pages. Its shadow far plane is its range rounded up to a power of two and never shrinks while it keeps the slot (`shadow_slots::shadow_range`): range follows intensity, and the flickering lamp's dropouts would otherwise reset its pages at every change. Writes each light's `shadow_slot` and `ShadowedLights::count` (one past the last used slot). Range = the light's radius, or for area lights where L·A/d² drops below 0.001 lx (≤ 50); one-sided area lights shadow from 2 cm in front of their emitter |
| `bvh_upload` | CPU build + upload | all non-`Blend` `Mesh`, in world space via `transform`. Rebuilt when the mesh **count** changes, or once transforms have been unchanged for 10 frames after a change (so dragging doesn't rebuild every frame). Each triangle gets its mesh's material factors × the mean of its albedo / metallic-roughness / emissive textures (cached per texture) × the average of its 3 vertex colors, plus its alpha coverage (`GpuTriangle::roughness_coverage`, unorm8 roughness + coverage; see Gotchas) | BVH nodes/tris/info |
| `probe_atlas` | upload | camera eye, `RenderDebugFlags` DDGI params | probe grid params (grid snaps to `probe_spacing` and centres on the camera, kept inside the scene's mesh bounds: a scene that fits gets one fixed grid covering all of it, a larger one slides only up to its edges. Camera-only centring left the far end of the hospital corridor outside the grid, with no indirect light, until the camera walked towards it. `cell_origin` is the grid origin in cells, for the atlas slots) |
| `probe_trace` | compute | BVH, probe params, sky/point/spot/area lights + counts | per-ray radiance + direction (864 probes × 128 rays, every 4th frame). Hits are lit by every light with one any-hit shadow ray each (`bvh_trace(.., any_hit = true)`). Local lights skip the ray when out of range or behind the surface, and the ray stops `SHADOW_BIAS × probe_spacing` short of the light. Area lights use the closest point. Single bounce: hits don't sample the probes. Cost grows with hits × lights in range. Binds 9 storage buffers, over WebGPU's default of 8 (fine with `adapter.limits()` on Vulkan). Hits add the triangle's emissive, so emitters bounce light into GI. Hit albedo is `(1 − metallic)·albedo·(1 − spec) + spec`, where `spec` is the env-BRDF reflectance seen from the probe, spread diffusely |
| `probe_update` | compute | rays, atlas[current] | atlas[1-current] (irradiance 8², visibility 16², 1px border), then flips `current_atlas`. Runs every 4th frame. A probe's atlas slot is its world cell modulo the grid (`probe_slot` in `probe_update.wgsl` and `lighting.wgsl`), so it keeps its history while the grid scrolls; storing probes by grid index made all indirect light pop each time the camera crossed a 5 m cell line. Visibility texels carry a tag of the world cell in blue; a slot whose tag doesn't match (a probe entering the grid, or the first update) takes the new rays at hysteresis 0 |
| `shadow` | raster | first `SkyLight`, camera, all meshes (`Blend` ones only into the glass tint maps) | 4-cascade 2048² depth array + `ShadowParams` (PSSM λ=0.75, sphere-fit, texel-snapped). Each cascade only draws meshes whose bounds reach its ortho box. Splits end at the farthest scene point and each cascade's depth range spans the world-space scene AABB, so shadows work at any scene scale. Opaque meshes use a depth-only, front-face-culled pipeline. `is_masked` meshes use an unculled pipeline (`vs_masked`/`fs_masked`) that alpha-tests albedo. That pipeline keeps its own copies of those meshes' albedo textures (`masked_textures`, keyed by `TextureAsset::id`, with key 0 = white fallback, pruned to live masked meshes every frame) and multiplies their alpha by the base color factor's Then **local light shadows** as **virtual shadow maps** (`light::virtual_shadow`, a scaled-down take on Unreal 5's): each face of a shadowed light (cube: +X −X +Y −Y +Z −Z at 90°; spot: one face along its direction; near 0.02, far = the rounded range) is an 8192² map with 7 mips, split into 128² pages (5461 per face), and only pages visible pixels request are backed by one of the 1024 physical 128² pages of a 4096² Depth32Float atlas (`local_shadow_map_id`). The page table (`local_pages_id`, a storage `u32` per virtual page of every slot's faces: physical page + 1, 0 = none; 4 MB) is uploaded per changed face. Each frame: a slot whose `ShadowCaster` changed (`renders_like`) or whose geometry signature did (geometry generation + key and transform of every mesh whose world bounds reach into the light's range) is reset: its pages are freed and the coarsest page of each enabled face (one page covering the face at 128²) is allocated pinned. Then the latest request mask from `shadow_pages` is applied: requested resident pages are marked used, missing ones get a free page or evict the least recently requested unpinned one not asked for this round, coarsest mips first so a full pool still serves fallbacks. Pending pages render: every pinned one (so a reset light is never without its coarse map) plus up to `LOCAL_PAGE_BUDGET` (64) others, coarsest first; each with the face's VP narrowed to the page (`PageKey::view_proj`: the page's part of the clip square stretched over all of it, depth unchanged), its own `ShadowView` at a dynamic offset (`LOCAL_VIEWS` = 192 + 64 slots), viewport + scissor on its physical page, cleared by a triangle at far depth (`vs_clear`), meshes culled against the page's frustum, with unculled, depth-biased copies of both pipelines (rooms see walls from both sides). A page's table entry is set once rendered. Moving lights (or geometry in range) therefore keep only coarse pages while they move. Faces (`LocalShadowFace`: VP, `info.x` = 1 if the face has pages, the light (origin + half size), face count + tan of half the fov + near + far) and `lod.x` (a screen pixel's world size per metre of view depth, from the camera) go to `LocalShadowParams` (`local_shadow_params_id`), slot-major at `slot * 6 + face`. **Glass tint maps**: every cascade (`glass_tint_id`, 1024² × 4) and every rendered local page (`local_glass_tint_id`, a 4096² atlas with the depth atlas's page layout, each page cleared by `vs_clear` / `fs_clear_tint`), both Rgba16Float, get tinted after their depth: cleared to (1, 1, 1, 1e4), then `Blend` meshes drawn unculled with `vs_glass` / `fs_glass` (group 2 = their sRGB albedo, `glass_textures`), rgb blended by multiply (transmittance `(1 − coverage) + coverage × transmission × (1 − F)ⁿ × tint`, with Schlick Fresnel at the light's actual incidence angle (so curved clear glass gets dark rims) and n = 2 for thin-walled surfaces, volumes take the square root per face plus Beer–Lambert), a by `Min` (depth of the glass nearest the light: clip z for cascades, clip w for cube faces). Metallic is ignored. Glass never enters the depth maps. The instance buffer and the per-view uniform (`ShadowView`: view-proj + light direction (w = 0, cascades) or origin (w = 1, cube faces)) are visible to the fragment stage here |
| `gbuffer` | raster | camera, non-`Blend` meshes (frustum-culled by `MeshDraw::bounds`) | albedo (texture × base color factor × vertex color), normal, material (`Rgba8Unorm`: roughness, metallic, AO (always 1 for now), 0), emissive (`Rgba16Float`: texture × factor × strength, linear, unexposed), transmission (`Rgba8Unorm`: diffuse transmission color, factor in alpha, cleared to 0), depth (reverse-Z, clear 0.0). Group 1 is a `MaterialTextures` bind group (glTF emissive is factor × texture, hence the white emissive fallback). Textures and bind groups no mesh uses any more are dropped every frame. Discards texels whose alpha (including the base color factor's) is below `alpha_cutoff`. Double-sided meshes go through a second unculled pipeline and flip their normal on back faces (`front_facing`) |

Coordinate conventions: right-handed, Y-up, camera looks down -Z. Light data is in **view space** on the GPU. Camera/GBuffer depth is reversed-Z (`GreaterEqual`, clear to 0). Shadow maps use standard Z (`LessEqual`).

## Light units
Lighting follows `KHR_lights_punctual`, so glTF intensities map 1:1. `SkyLight::intensity` is illuminance in lux, `PointLight`/`SpotLight::intensity` is luminous intensity in candela, and `AreaLight::intensity` is the emitter's luminance in nits. `lighting.wgsl` shades every light with one Cook-Torrance BRDF: GGX, height-correlated Smith visibility, Schlick Fresnel, `F0 = mix(0.04, albedo, metallic)`, diffuse `(1 − F)(1 − metallic)·albedo / π`. Perceptual roughness is clamped to `MIN_ROUGHNESS` (0.045) against fireflies. `probe_trace.wgsl` reflects light diffusely, with the triangle's specular reflectance folded into its albedo (see the pass table). Point/spot falloff is `window(d / radius)² / d²` (`range_attenuation`), so `radius` is the glTF `range`. The spot cone uses the spec's squared linear blend between `outer_cos` and `inner_cos`. The sky background (and the probes' sky term) scales with each sky light's illuminance. The camera's `exposure` (carried in `ClusterParams`) brings physical values into display range: 1.0 suits a few-lux scene, and daylight (~100 000 lx) wants roughly 2⁻¹⁵.

## Gotchas
- **Mesh geometry is keyed by its `Arc`s** in `GeometryArena` (instance slots by `EntityKey`), and every mesh texture cache (`gbuffer`, `shadow`, `bvh_upload`) by `TextureAsset::id`, a process-unique counter. Never key a cache by `Arc` address: after a hot reload the new textures reuse the freed old addresses and the cache returns the wrong texture (`capture --reloads N` reproduces this). `SpritePass` still keys `SpriteTexture`s by `Arc` address. Changing a `Mesh`'s vertices in place is never re-uploaded (and would change every mesh sharing them), but giving it new `Arc`s or replacing the entity works. `Mesh::transform` *is* picked up every frame. Removed meshes are freed on the next frame. `Mesh::material` factors go through `GpuModel` every frame, so they can be edited live. Cut-out (`Mask`) triangles carry their alpha coverage into the DDGI BVH: `TextureAsset::coverage` samples a grid over the triangle's UVs for texels passing `cutoff / base color alpha`; fully cut-out triangles are dropped, and `probe_trace` lets rays (and shadow rays) through a partly covered one with probability 1 − coverage (a PCG stream seeded per ray and frame), so the probes' temporal blend averages it into partial occlusion. `Blend` meshes are invisible to everything but `transparent` and `shadow`'s glass tint maps: no depth, no opaque shadow, no GI occlusion (GI rays pass glass untinted), not reflected by SSR (they do reflect opaque geometry themselves, see `transparent`).
- Editing vertices in place at a constant mesh count leaves DDGI tracing stale geometry (the BVH only watches count and transforms). The same goes for material edits: per-triangle materials only refresh on a rebuild. Negative-determinant transforms (mirroring) flip winding and get back-face culled.
- "Main camera" is `get_entities::<Camera>().first()` in several passes. With multiple cameras, which one wins depends on slotmap order: after `World::clear`, freed slots are reused highest-first, so entities added later iterate *before* earlier ones.
- `lighting.wgsl` holds two paths: the deferred fullscreen `vs_main`/`fs_main` (group 0 = G-buffer, bindings 0–5) and the forward `vs_forward`/`fs_forward`/`fs_background`/`fs_scene_copy`/`fs_scene_downsample` used by `transparent` (group 0 bindings 1, 3, 4, 6–8, 10 and 17–18 — reusing the deferred `t_normal`/`t_depth`/`s_linear` declarations at 1/3/4 — and group 5). Both share `direct_lighting`, `sample_probe_irradiance` and the BRDF helpers. A layout only needs the bindings its entry points use. The deferred path also binds `t_ao` at 16. `direct_lighting` names `t_depth` and the glass targets (contact shadows), so every entry point calling it needs bindings 3, 17 and 18 even with contact shadows off: the reflection probe capture binds 1×1 stand-ins there. A third set of entry points, `vs_probe` / `fs_probe_depth` / `fs_probe` / `vs_probe_sky` / `fs_probe_sky`, is the `reflection_probe` capture: group 0 bindings 7 (instances) and 11 (`ProbeCapture`, dynamic offset per face), groups 1–5 as the forward path. `direct_lighting(..., probe_capture)` then loops every point light (the camera's clusters don't apply) and takes the sky shadow from the first cascade containing the point, treating uncovered points as shadowed. Group 3 bindings 5–7 (reflection cube, `ReflectionProbeParams`, trilinear sampler) are part of `LightingBindings`. The forward path reuses `t_normal` (1), `t_depth` (3) and `s_linear` (4) with the same types; any other new group-0 binding must not collide with the other path's. A fourth set, `vs_particle` / `fs_particle` (`particles` pass), uses group 0 bindings 3 (`t_depth`), 12 (particle slots), 13 (`ParticleParams`, whose structs are duplicated from `particle_sim.wgsl`) and 14 (the draw list).
- WGSL structs/constants are duplicated by hand (no shader includes). Keep the Rust `#[repr(C)]` structs (`ClusterParams`, `ProbeGridParams`, `ShadowParams`, `CameraUniform`, `DebugFlagsGpu` (also declared in `ssr.wgsl`), `Gpu*Light`) and constants (`PROBE_GRID_DIM`, `PROBES_PER_ROW/COL`, `CLUSTER_*`, `NUM_CASCADES`) in sync with `sandbox/shaders/*.wgsl`.
- Only point lights are clustered. Spot (≤64) and area (≤32) lights are looped over for every pixel in `lighting.wgsl`, so keep their counts low. Area lights use a representative-point approximation (diffuse: closest point on the rectangle; specular: where the reflection ray meets it, with roughness widened by the equivalent disc radius, Karis 2013), are two-sided unless `two_sided` is false, and treat `right` / `up` as **half-extent** vectors. Only the up to 32 lights with a shadow slot cast shadows in direct lighting (atlas); all lights are shadowed in GI (`probe_trace`, BVH rays).
- The GBuffer stores **world-space** normals but local lights are in view space. `lighting.wgsl` converts the normal to view space (`N_vs`) for point/spot/area lights. Sky lights convert `L` to world space instead.
- `pass/sdf_voxelize.rs` is **not** in `pass/mod.rs`, so it is dead code. Wire it in or delete it.
- `Renderer::new` / `new_headless` use `adapter.limits()` and only the timestamp features the adapter supports. The GPU profiler activates only if `TIMESTAMP_QUERY | TIMESTAMP_QUERY_INSIDE_ENCODERS` are present.
- The surface (and the headless target) is sRGB, so passes output linear color. The egui overlay gets a non-sRGB view of the same texture.
- `Renderer::resize` ignores 0×0 sizes and clamps to `max_texture_dimension_2d`.
- `RenderDebugFlags` is shared by `Arc<RwLock>` between `DebugLayer` (render-thread UI), `ProbeAtlasPass`, `LightingPass` and `DebugOverlayPass`. To control it from outside, inject your own with `RenderGraphPBRBuilder::with_debug_flags` (the editor does this).

## 2D path (`rendering_2d`)
`SpriteRenderGraphBuilder` builds a single `SpritePass` that writes straight to the surface. A `SpritePass` can also be added to another graph as an overlay (pass `None` as the clear color). It sorts sprites by ascending `z_order` (painter's order), uploads all instances in one `FrameArena` allocation, and draws each run of consecutive sprites sharing a texture as one instance range (the cache is keyed by `Arc<SpriteTexture>` pointer). Instanced quads have per-instance TRS, color and `uv_rect` for atlases. `Camera2D { position, zoom }` gives an orthographic, Y-up projection in pixel units. The first `Camera2D` is used, or the default if there is none.
